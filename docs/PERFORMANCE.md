# 实测性能与边界

以下性能数据在项目更名为 `ts-backtest` 之前测得，原始记录保留当时的名称、路径和代码哈希；更名后的正确性与分发包另行验证，没有把更名操作算成新一轮性能测量。

冻结代码在本机单证券 **1,000,000 根分钟 Bar、9,998 次成交**的热回测中，5 次样本的 p50 为 **3.326 秒**，p95 为 **3.543 秒**。没有达到原设计的“百万 Bar 小于 2 秒”目标。24 万根、2,398 次成交的 p50 为 **0.784 秒**。这些是实测结果，不从小样本外推。

原始数据与逐样本数据见 [完整场景](evidence/benchmark.json)、[最终代码复测](evidence/benchmark-final-hot.json)。完整测试包含 14 个独立子进程场景；冻结修复后额外复测热引擎、异常数据及 Node 22，并重测进程冷启动。JSON 逐场景记录实际构建 SHA、数据哈希、样本、指标和资源信息。最初两个长 IO 场景的模块 SHA 来自修改前的独立快照；其 IO 数据未冒充最终修复版热引擎测量。

## 环境与口径

- CPU：AMD Ryzen 7 5800H with Radeon Graphics；16 个逻辑 CPU，内存 30.69 GiB；linux x64，内核 7.0.0-31-generic。
- 主基准 Node v24.18.0；Node 22.23.4 另测核心、冷启动与生产包。Windows、macOS、Bun 没有实测。
- 每项正常计时至少 5 样本，百分位采用 nearest-rank；5 样本的 p95 等于最大值，不是稳定的尾部延迟估计。机器与开发任务共享，没有 CPU 隔离、频率锁定或清空操作系统文件缓存。
- 热运行前执行 1 次不计入统计的 JIT 预热。正常计时不启用 CPU/Heap profiler，`measurePhases` 为 false，`indicatorMs/engineMs` 的 null 表示未测量，不能当作 0。
- 普通 IO 使用操作系统缓存，不执行 fsync。端到端从已有 CSV 的导入开始，到结果原子发布结束；不含合成数据生成、文件首次生成或 Node 启动。数据规范化、策略校验和核心模拟均真实执行。
- 数据是确定性的三角价格序列，显式标记为 **每天都是合成交易日**，包含周末；不冒充真实市场交易日历。日线组合使用足以覆盖组合的显式初始资金。全部成本、滑点、T+0 与手数规则见 `scripts/benchmark-fixture.ts`。
- 大型 SDK 导入测试将 `maxFileBytes` 显式设为 512 MiB、行预算 200 万，缓存校验预算 512 MiB。它们不是默认 64 MiB 导入预算下的 MCP 测试；实际部署仍须配置合适的资源预算。

## 冷数据与端到端成本

下表属于第一次完整场景运行，正常计时 5 样本。CSV、缓存和校验实现与最终复测一致；最终热引擎数字以上一节为准。

| 阶段 | 240,000 Bar p50 / p95（秒） | 1,000,000 Bar p50 / p95（秒） |
| --- | ---: | ---: |
| CSV 读取 + 字段校验 + 规范化 | 6.527 / 6.534 | 27.955 / 28.019 |
| 列式缓存编码 | 0.180 / 0.205 | 0.769 / 0.906 |
| 缓存写文件 | 0.028 / 0.039 | 0.155 / 0.175 |
| 缓存读文件 | 0.020 / 0.032 | 0.087 / 0.090 |
| 缓存解码 + 校验和 + 重新规范化验证 | 5.748 / 5.773 | 23.645 / 23.952 |
| summary 结果写入及原子发布 | 0.002 / 0.005 | 0.005 / 0.008 |
| CSV → 回测 → summary 产物（端到端） | 7.322 / 7.391 | 30.947 / 32.872 |

百万 Bar 的 CSV 为 94,000,077 bytes，缓存为 113,389,060 bytes；整个导入/编解码/重复回测子进程峰值为 **2776.58 MiB RSS**。缓存当前强调可移植和完整性校验，冷解码仍会重建并重新验证数据，不能宣传数量级的冷加载加速。参数扫描的候选之间共享并复用已验证的列式数据；普通 prepare/validate/run/explain 作业仍各自进行导入或解码及校验，SDK 热运行数值不能代替普通 MCP 请求时延。尚未实现普通作业的数据 LRU 缓存。引擎不是 out-of-core 系统。

`resultWrite` 的主场景使用 summary，小产物写入时间不代表 fullTrace。部分成交场景使用 fullTrace：24,000 Bar、11,900 次成交，产物写入 p50 为 0.363 秒，完整 CSV→结果为 1.892 秒。

## 独立参数扫描与 Walk-forward

| 参数组 × 每组 Bar | Worker 数 | 实际参数组 × Bar 总量 | p50 / p95（秒） | 子进程峰值 RSS（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 100 × 24,000 | 1 | 2,400,000 | 8.862 / 9.021 | 297.07 |
| 1000 × 2,400 | 1 | 2,400,000 | 9.582 / 11.668 | 351.96 |
| 100 × 24,000 | 4 | 2,400,000 | 2.837 / 2.977 | 652.30 |
| 1000 × 2,400 | 4 | 2,400,000 | 3.204 / 3.547 | 668.69 |

上述每项完整执行全部候选；0 个失败候选。单 Worker 与 4 Worker 的全部候选结果摘要、种子和执行指纹一致，另外有 8×2,400 的小金标并发对照。时间包含共享数据准备、Worker 启动、调度、模拟和结果汇总，不只是计算内核。GC 观察器只覆盖主 isolate；Worker GC 没有被错误记成“总 GC 为 0”。

连续 Walk-forward 使用 2,400 根分钟 Bar、10 个观测交易日，4 日训练 / 2 日测试，3 个连续样本外窗口，每窗 3 个候选、2 Worker。p50 / p95 为 **0.626 / 0.680 秒**。保留持仓和未完成订单，样本外使用同一个账户；相邻窗口边界及训练先于测试已断言。预算口径为 21,600 训练候选×输入行 + 2,400 行连续运行，并未把多个窗口收益简单拼接。

## 进程冷启动、GC 与分配

| Node | 入口 | 进程创建 + import p50 / p95（毫秒） |
| --- | --- | ---: |
| v24.18.0 | 编译后模块目录 | 135.63 / 137.14 |
| v24.18.0 | 生产 core.cjs | 94.32 / 97.08 |
| v22.23.4 | 编译后模块目录 | 130.59 / 131.99 |
| v22.23.4 | 生产 core.cjs | 125.17 / 129.48 |

冷启动指新 Node 进程，不是磁盘冷缓存。生产包的 Node 22/24 外部解压、空 PATH/NODE_PATH、禁网络、SDK/CLI/MCP/研究 Worker/可选格式烟测见 `dist/package/smoke-report.json`；体积见 `dist/package/size-report.json`，压缩大小与解压大小分开。

240k 首次完整场景热运行的 GC 事件数为 30/30/30/30/30，GC duration 为 23.44/23.89/22.53/25.59/24.79 ms。通过 PerformanceObserver 收集，并在计时区间之后让事件循环投递，避免同步代码结束时错误报告零 GC；这些 duration 不是精确的所有线程停顿总量。

独立 HeapProfiler 采样使用 32 KiB 采样间隔，包含已回收对象，估算分配 **1.913 GiB**、62,534 个样本。它是带采样开销的统计估算，不是精确总分配；该诊断运行耗时 0.997 秒，未并入正常 p50/p95。heap delta 仅报告保留堆变化，可能为负，不替代分配总量。

同一 240k 输入开启逐阶段计时的单独诊断运行耗时 1.646 秒，对比正常热运行 p50 0.746 秒，说明频繁 clock 调用会明显增加开销。早期 `benchmark-output/pre-optimization-240000.json` 的 3.943 秒也同时开启 CPU profiler 和阶段计时，不能直接作为与正常样本严格可比的“加速倍数”。

## 复现

```bash
npm ci
npm ci --prefix optional-formats
npm run package
npm run benchmark:quick
npm run benchmark
node scripts/benchmark.mjs --final-hot --samples=5
node scripts/render-benchmark.mjs
npm run test:package
```

脚本将大型 CSV/缓存放入系统临时目录，每个场景完成后删除，只保留小 JSON 报告；全部场景串行运行。若没有本地 Node 22 二进制，脚本会明确只运行当前 Node，不冒充跨版本验证。原始报告记录此轮确实执行的版本与场景。Node 性能/内存口径参见 [PerformanceObserver](https://nodejs.org/api/perf_hooks.html#class-performanceobserver)、[resourceUsage](https://nodejs.org/api/process.html#processresourceusage) 和 [HeapProfiler 采样协议](https://chromedevtools.github.io/devtools-protocol/tot/HeapProfiler/)。
